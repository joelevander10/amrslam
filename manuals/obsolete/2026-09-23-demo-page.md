## 1. What it is

A single full-screen page on the vehicle's own kiosk panel (~1280×720 CSS px, touch)
for when the AGV is on display. The audience is purchasing, plant GMs and directors,
and people shopping for material handling. They are not engineers.

| It is | It is not |
|---|---|
| a brochure that moves: product story + 4 live friendly numbers | a diagnostic or operator page |
| read-only (GET only) | a way to command, arm, load or reset anything |
| reachable from both Op and Eng without a PIN | behind the engineer guard |
| brighter, bigger, fewer words | in the `amr.css` engineering look |

Decisions taken (2026-09-23 Q&A): vehicle panel only · a few live values · pitch
**both products** (tape AGV now, SLAM AMR upgrade) · English only.

## 3. Live panel: what is shown, and from what

A new endpoint `GET /api/demo` returns only friendly, pre-worded fields. All wording
is decided **on the server** in one pure function, so the browser never receives a
fault code, a reason string or a hex number.

| Tile | Value | Source (`adapter.state()`) |
|---|---|---|
| Status sentence | see table below | `mode`, `run`, `line`, `drives`, `panel` |
| Speed | km/h, 1 decimal, 0 when stopped | mean of `mux.left_rad_s` / `right_rad_s` × wheel radius (profile `vehicle.wheel_dia_m / 2`) |
| Distance | m driven since the demo started | integrated server-side from the same speed; reset when the web process starts or `/demo?reset=1` is opened |
| Safety stops | count since the demo started | rising edges into run `BLOCKED` with `hold_cause=field`, or line `HOLD` with `hold_cause=field` |
| Mode | "Tape following" / "Free navigation (no tape)" / "Standing by" | `mode` (LINE / NAVIGATION / other) |

Status sentence mapping (the whole vocabulary; nothing else is ever shown):

| Condition | Dot | Sentence |
|---|---|---|
| run EXECUTING or line RUNNING | green | "Driving the route" |
| hold cause `field` (either layer) | amber | "Someone is in the way. It waits, then continues by itself." |
| run READY / line ARMED | blue | "Ready. Press Start on the vehicle to begin." |
| run PAUSED/DONE, line HOLD/DONE (not field) | blue | "Paused between runs" |
| any FAULT, E-stop, drives off, stale data, no layer | grey | "Standing by for the next demonstration" |

Faults deliberately read as "standing by": the demo page is not where anyone
diagnoses anything, and a red screen in front of a customer helps nobody. The
operator's Home page still shows the truth.

Poll every 1 s. If `/api/demo` fails, the live panel keeps its last values and goes
to "Standing by" after 5 s; the story side keeps running (no server dependency).

## 4. Story cards (content, not code)

All text, specs and image names live in **one editable file**,
`amr_web/static/demo/content.json`, so marketing edits do not touch code. Images in
`amr_web/static/demo/` (JPEG/WebP, ≤ 300 kB each). Draft wording, to be approved:

1. **Two products, one platform** — start with magnetic tape today; upgrade the same
   vehicle to tape-free navigation when the layout changes.
2. **Tape AGV** — follows a magnetic strip on the floor; stops at stations marked by
   tags; fast to install, changed by moving tape.
3. **Tape-free AMR** — drives around the site once to learn it; routes are drawn on
   a tablet; no floor work.
4. **Safety first** — a laser safety scanner watches the path; slows and stops for
   people; emergency stop buttons on the vehicle.
5. **Key specs** — tile grid: payload / towing capacity, top speed, battery and run
   time, charging, navigation, safety. **Values are placeholders (`TBD`) until
   supplied**; no number is invented.
6. **Fits your factory** — local engineering and service in Indonesia; contact line
   and QR code image slot.

## 5. Look

- Scoped stylesheet `static/demo.css`, all colours as tokens on `.demo` (does not
  touch `amr.css`): white background, one saturated brand colour (placeholder
  `#0B6BCB`), one warm accent (`#FF8A00`) for numbers, green/amber/blue/grey dots.
- Numbers 64–80 px, sentences 28–32 px, card body 22 px. Readable from 2 m.
- Soft card shadows, 16 px radius, 400 ms cross-fade between cards. Nothing blinks.
- Existing self-hosted fonts (Archivo headings, Plex Sans text). No CDN: the kiosk
  has no guaranteed internet.
- `prefers-reduced-motion`: cards switch without the fade.

## 9. Revision: a stationary display unit (2026-09-23)

The demo vehicle never moves, so every motion number read 0 forever. Replaced:

| Before | After |
|---|---|
| Status sentence from run/line/drive state (5 sentences) | 3 sentences from the scanner: watching / "It sees you" / standing by |

| Specs as one rotating card | Specs as a fixed 4-tile strip under the cards |

Source: `adapter.live.pose_scan()` (scan points and base pose in the same world
frame), rotated back into the vehicle frame in `demo.py`; stale (> 2 s), missing or
frame-mismatched data = standby. Points inside the outline (own body) are dropped.
`/demo?reset=1` and the wheel-radius plumbing are removed. The demo files are
exempt from the engineering-look style guard in `test_server.py` (they have their
own look, §5).
