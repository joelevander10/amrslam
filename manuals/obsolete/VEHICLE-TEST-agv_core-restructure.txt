ROLE
You are verifying a completed code restructure on a live 150 kg differential-
drive AGV. The refactor moved library code into a Python package and changed how
every process finds it. It was verified on a Windows dev box as far as that box
allows: 898 offline checks run there with a fake `fcntl`, and the failure set is
byte-identical to the pre-refactor baseline. What could NOT be verified off the
vehicle is exactly what you are here to check: the owner lock (needs real
fcntl/flock), /proc reads, the colcon install space, PYTHONPATH reaching ROS
nodes, systemd, and any motion at all.

HARD RULES
  * The vehicle moves. Blocks under the wheels before ANY armed step. No
    exceptions, including "just a quick jog".
  * Stop at the first failure. Report what failed with the exact output. Do not
    "fix forward" past a failed step.
  * You may fix an environment problem (a missing pip package, a stale colcon
    overlay, a wrong PYTHONPATH). You may NOT edit production code in agv_core/,
    amr_ws/src/, canworker.py, app/ or profiles/ without asking first.
  * The legacy controller (main.py + app/ + canworker.py) and the ROS stack both
    open can0. NEVER run both at once. Section 6 depends on this.
  * If something is ambiguous, say so and stop. Do not guess on a vehicle.

WHAT CHANGED (so you know what a failure is pointing at)
  config.py            -> agv_core/config.py
  core/<name>.py       -> agv_core/<name>.py
  drivers/<name>.py    -> agv_core/drivers/<name>.py
  drivers/canbus/*.py  -> agv_core/drivers/canbus/*.py
  Bare imports (`import config`) are now package imports (`from agv_core import
  config`). The sys.path layer-directory loops in main.py, canworker.py,
  app/server.py and tests/helpers.py are gone.
  amr_ws/src/amr_base/amr_base/agv_repo.py is DELETED. ROS nodes import agv_core
  directly; the repo root reaches PYTHONPATH via amr_ws/deploy/amr-launch.sh and
  amr_ws/env/vehicle.sh.
  UNCHANGED and still shipping: main.py, app/, canworker.py, profiles/.
